# Prompt Pack Schema

Each prompt pack produced by **zodiac** should be JSON-serializable and easy for
another agent to use.


## Required Attribution

Every published prompt pack must include:

- original repository URL
- owner/name
- license key
- default branch commit SHA
- capture timestamp
- file-level citations for all major claims
- three top-level documents: trend report, application report, rebuild prompt
- a generated single HTML page suitable for teach-server hosting

## Citation Requirements

Every important claim must be backed by `source_notes[]`. Prefer commit-pinned
GitHub blob URLs with line ranges.

Minimum citation coverage:

- trend report: repository metadata, README, docs, release notes, or source
  citations that support why it is timely or notable
- application report: README, examples, docs, APIs, or tests that support
  possible use cases
- rebuild prompt: source notes that support required behavior and structure
- project purpose: README or documentation citation
- license: license file or GitHub license metadata citation
- build/runtime assumptions: manifest, config, or README citation
- behavior: README, docs, source files, or tests citation
- file map: source tree or path-specific citation
- prompt instructions: source note ids that support the requested behavior

If line numbers are unavailable, use `"lines": "unknown"` and still include the
commit, path, and URL.

## Static-Only Analysis

Prompt packs are generated by reading repository contents, not by executing
them. The analyzer may use GitHub API responses or a shallow clone at a pinned
commit for file access and line-numbered citations.

Do not run candidate repository commands such as `npm install`, `npm test`,
`pip install`, `cargo build`, `go test`, `make`, package scripts, shell scripts,
or project binaries.

## Generation Guidance

The prompt pack should describe the project at the level of behavior,
architecture, trend rationale, and applications. Do not paste large source
files. Small signatures, command names, route names, and configuration keys are
acceptable when needed for clarity.
